## ⓪-2 아이가 제 폰을 쓸 때가 통째로 빠져 있었다 ★★ (2026-08-16)

**이 앱에서 가장 크게 어긋났던 자리다.** 부모 폰에서 아이는 두 종류다.

| | 학습 기록이 있는 곳 |
|---|---|
| 이 폰에 만든 아이 프로필 | 부모 폰 안 |
| 📲 다른 폰의 아이 (QR 로 연결) | **아이 폰 안.** 부모 폰에는 하루 한 줄 요약만 왔다 |

회원님 아이 셋은 전부 아래쪽인데, **확인은 위쪽으로만 했다.** 그래서 「부모 폰에서
달력을 볼 수 있다」 고 말했는데 회원님 화면에는 그 단추조차 없었다. 안내 문구만
새것이라 「📅 를 누르면 달력이 열립니다」 라고 적혀 있고 정작 📅 가 없었다.

### 통로를 넓혔다

리포트에 **갈래별 성적과 틀린 낱말 id** 를 실어 보낸다. 낱말 이름은 안 보낸다 —
부모 폰에도 같은 어휘가 있어 id 로 찾는다. 배운 낱말(단어장)은 안 보낸다(하루
서른 개가 넘는 날이 있어 알림에 안 들어간다). 요청권도 양방향으로 뚫었다:
아이가 신청 → 부모 폰 목록에 쌓임 → 승인 → **결과가 아이 폰으로 되돌아감.**
되돌아가는 길이 아예 없어서, 부모가 승인해도 아이 화면은 「기다리는 중」 이었다.

### 화면

- **부모 홈 → 아이들 학습 보고서** 가 이제 「아이별 설정」 이 아니라 아이 이름
  버튼 셋으로 간다. 아이를 누르면 달력, 날짜를 누르면 국어·영어가 갈라진다.
- **달력을 줄이고 날짜 카드를 달력 바로 아래로 올렸다.** 예전에는 「이 달 요약」 과
  「성적표」 뒤에 있어서 눌러도 화면 밖이었다 — 「달력이 너무 크다」 의 원인.
- **정답률에 분모를 적는다.** 「5개 · 정답률 93%」 는 "다섯 개 중 93%" 로 읽혔다.
  낱말 다섯이 열다섯 문제가 되기 때문이다. 이제 「낱말 5개 · 14/15문제」.
- **틀렸는데 「다 맞혔어요」 라고 하던 것을 고쳤다.** 정답률 75% 아래에 그 말이
  적혀 있었다. 이제 낱말을 못 찾으면 「3문제 틀렸어요」 라고 밝힌다.
- **요청권을 단추 넷으로 세웠다.** 못 채운 것은 꺼진 채로 무엇을 더 해야 하는지
  적는다. 25일 채우기 · 영어 레벨 · 국어 레벨 · 오늘치.
- 「공부하자고 조르기」 → **「공부하세요!!!」**, 아이마다 따로 보낸다.
- 아이 폰 달력에 **그날 배운 낱말**을 넣었다(오답 노트·단어장을 옮겨 온 것).
- 판 번호에 **만든 때**를 적는다 — `0.23.0.17 · 2026.08.16.09.30`.

### 데인 것

- **`open(p,'w')` 는 쓰기 전에 파일을 비운다.** 파이썬으로 파일을 고치다 예외가
  나서 `calendar.tsx` 433줄이 통째로 날아갔다. 커밋되어 있어 살았다.
  **파일을 고칠 때는 Edit 도구를 쓸 것.**
- **e2e 를 다른 작업과 같이 돌리지 말 것.** 그림을 만들면서 같이 돌렸더니
  6초 대기를 넘겨 멀쩡한 검사 둘이 빨개졌다. 단독으로 돌리면 통과한다.
- **e2e 가 실제로 누락을 잡았다.** 요청권을 단추 넷으로 바꾸면서 「지난달치
  청구」 를 통째로 빠뜨렸는데, 화면만 보면 멀쩡했다.

## ⓪ 2026-08-15 에 고친 것

### 1. 국어를 풀다 마지막에 화면이 비어 막히던 것 ★

**아이가 국어 공부를 끝낼 수 없었습니다.** 틀린 낱말은 판 끝에 한 번 더
나오는데, 그때 예문을 한 칸 넘기면서 **빈칸을 못 뚫는 문장**에 걸리면 화면이
통째로 비었습니다. 「23/24」 만 적힌 채 누를 것이 하나도 없고, 오류도 안 나서
아무도 몰랐습니다.

원인은 재출제할 때 갈래를 안 가리고 빈칸 문제로 못박은 것이었습니다. 국어
예문에는 표제어가 그 모양 그대로 안 들어 있는 것이 있습니다. `koGameFor` 가
이미 그 판단을 하고 있어서(빈칸을 못 뚫으면 뜻 문제로 내림) 그것을 부르게
고쳤고, 그래도 못 낼 때를 위해 「넘어가기」 를 두었습니다.

### 2. 결과 화면의 「오늘 틀린 단어」 가 국어를 못 찾던 것

두 가지가 어긋나 있었습니다. **국어를 아예 안 찾았고**(영어와 일상 문장
목록에서만 뒤짐), **하루 기록을 보고 있었습니다**(아침에 영어에서 틀린 것이
저녁 국어 판 결과에 올라옴). 판을 끝낸 쪽이 자기가 틀린 id 를 넘기게 했습니다.

### 3. 날짜별 학습 보고서를 국어·영어로 갈랐습니다

부모 홈 → 아이들 학습 보고서 → **📅 〇〇 학습 보고서 보기** → 달력 → 날짜.

```
8월 15일 (토) · 목표 달성 · 15/15 · 정답률 84%
  영어       5개 · 정답률 93%   (자주 틀린 낱말)
  국어       6개 · 정답률 83%   (자주 틀린 낱말)
  일상 문장   4개 · 정답률 75%
```

**하루 기록에 갈래별 칸을 새로 만들었습니다**(`bySubject`). 합계를 나중에
갈래로 되돌릴 방법이 없기 때문입니다. 이 칸이 생기기 전에 공부한 날은
「나눠 적기 전이에요」 라고 밝힙니다 — 어림잡아 채우면 아이가 받은 적 없는
정답률이 부모 화면에 뜹니다.

### 4. 보상을 매일 쌓는 방식으로 바꿨습니다

```
하루치를 다 마침  → 아이가 「📗 오늘 공부 다 했어요 — 500원 받기」
                  → 부모가 승인하며 한마디  → 저금통에 쌓임
달이 바뀜         → 아이가 「🗓️ 7월에 모은 12,500원 청구하기」
                  → 그달 25일을 넘겼으면 부모가 공로금을 얹어 승인
                     (12,500 + 5,000 = 17,500원)
```

**「한 달 개근」 은 없앴습니다.** 하루도 안 빠져야 받는 것이라, 중순에 한 번
빠지면 남은 보름을 버틸 이유가 사라졌습니다. 레벨업 요청권은 그대로 둡니다.

금액은 부모 설정에서 바꿉니다(하루치 기본 500원 · 공로금 기본 5,000원).
못 받고 넘어간 달은 사라지지 않고 다음 달에도 보입니다.

### 5. 워크트리에서 `npm test` 가 시험을 하나도 못 찾던 것

`testMatch` 에 `<rootDir>` 로 시작하는 절대 glob 을 썼는데, 윈도에서 역슬래시
경로로 바뀌고 glob 이 그것을 이스케이프로 읽었습니다. `roots` 로 바꿨습니다 —
**이제 워크트리에서도 36묶음이 그대로 돕니다.**

- `npm run check-meanings` — 뜻에 남은 줄바꿈 자국을 찾는다. 네 가지 모양을
  본다(홀로 못 쓰는 조각 · 한 글자가 떠 있음 · 괄호 옆이 벌어짐 · 쉼표 뒤가
  붙음). **못 잡는 것도 있습니다** — 「0개」 가 다 맞다는 뜻은 아닙니다.
- `npm run apply-meanings` — 표의 뜻을 앱에 갈아 끼운다. 넣기 전에 위 검사를
  먼저 돌려, **자국이 하나라도 남아 있으면 아무것도 안 하고 멈춥니다.**
  뜻이 여럿인 낱말은 건드리지 않고 목록으로 보여 줍니다. 긴 뜻은 앞 다섯
  개만 남깁니다(`--keep=N` · 안 자르려면 `--keep=0`).
- `node scripts/move-level.mjs <낱말>=<학년>` — 낱말을 다른 레벨로 옮긴다.
  배치표 · placement.json · 레벨 파일 **세 곳을 한 번에** 맞춥니다.
- `python scripts/batch-to-xlsx.py` — 넣은 낱말을 엑셀 한 장으로 뽑는다.
  마크다운으로는 한 화면에 몇 개밖에 안 들어와 224개를 훑기 어려웠습니다.

**조용히 어긋나던 것 둘을 고쳤습니다.**

- `npm run bump-data` 가 **판 번호만 올리고 목록에는 새 줄을 안 넣었습니다.**
  이 저장소의 `.ts` 는 CRLF 인데 도구가 `'…[\n'` 으로 찾고 있었습니다.
  줄 끝을 파일에서 알아보게 고쳤고, 못 찾으면 멈추게 했습니다.
- `npm run e2e` 의 「낱말 개수가 함께 나온다」 가 **`영어 3690개` 를 박아 두고
  있었습니다.** 초등 낱말 108개를 뺐을 때 3582 가 되면서 그 줄만 빨개져
  있었습니다(137개 중 136개 통과였습니다). 어휘 판에서 읽어 오게 고쳤습니다.

**e2e 를 돌리실 때** — 낱말을 고친 뒤에는 `npm run preview` 를 **다시**
켜세요. 미리보기는 구워 둔 것을 내놓기 때문에, 켜 둔 채로 데이터를 고치면
옛 낱말 수가 그대로 나와 이 검사가 빨개집니다. 실제로 한 번 그랬습니다.

## 노트북에서 확인하기

```bash
npm run preview      창 하나에 켜 둔다

npm test             658개
npm run preflight    빌드 전 점검
```

`localhost:8088`(아이) / `127.0.0.1:8088`(부모).

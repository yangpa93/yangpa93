# 곰탱이보카

중1~고3 한국 영어 시험 필수 단어·숙어를 **매일 10~20개씩, 틀린 것 위주로 반복**해서 익히는 모바일 앱입니다.
아이가 여러 명이면 프로필을 나눠 쓰고, 부모님은 같은 앱의 잠긴 영역에서 매일 리포트를 받고 보상 요청을 승인합니다.

Expo(React Native)로 만들어 iOS·Android에서 그대로 돌아가고, **서버 없이 기기 안에서만 동작**합니다.

## 시작하기

Node.js 18 이상이 필요합니다 (`node --version`으로 확인).

```bash
git clone -b claude/english-vocab-learning-app-pfy9yg https://github.com/yangpa93/yangpa93.git
cd yangpa93/vocab-app
npm install
npm start
```

## 어떻게 반복 학습이 되나

### 오늘 나올 단어를 고르는 규칙

`src/srs/session.ts`

기본값(새 단어 10 · 복습 10)이면 이 순서로 채웁니다.

1. **복습할 때가 된 단어** — 예정일이 오늘이거나 지난 것. 우선순위가 높은 순으로 최대 10개.
2. **새 단어** — 그 위에 10개를 얹습니다. **복습이 밀렸다고 새 단어가 줄지는 않습니다.**
   진도가 멈추면 1년이라는 계획이 무너지기 때문입니다.
3. 복습도 새 단어도 모자라면 아직 안 외운 단어 중 급한 것부터 당겨옵니다.

우선순위는 이렇게 매깁니다 (`src/srs/scheduler.ts`의 `priority`).

```
예정일이 지난 일수 × 4
+ 틀린 횟수 × 12
+ 오답률 × 25
+ (한 번도 못 맞힌 단어면) 20
− (이미 외운 단어면) 40
```

**오답이 쌓인 날은 복습 10칸이 전부 틀렸던 단어로 찹니다.** 잊지 않게 하는 것이 우선이라는
요구사항을 그대로 옮긴 동작입니다. 밀린 복습을 몰아서 정리하고 싶으면 부모님 모드에서
`하루 새 단어`를 잠시 낮추고 `하루 복습`을 올리면 됩니다.

### 간격이 벌어지는 방식

SM-2를 아이들 시험 대비에 맞게 손봤습니다.

- 맞히면 `1일 → 3일 → 7일 → 14일 → 30일 → 60일`로 완만하게 벌어집니다.
- **틀리면 간격이 0으로 돌아가고, 그날 세션 안에서 한 번 더 나옵니다.**
- 반복해서 틀리는 단어는 난이도 계수(ease)가 깎여서, 같은 단계라도 더 자주 돌아옵니다.
- 간격이 **21일**을 넘기면 "외운 단어"로 봅니다.

### 레벨 시험 응시 자격

한 레벨 단어의 **90%가 21일 간격을 넘기면** 레벨 시험을 볼 수 있습니다.
시험은 아이가 직접 눌러서 시작합니다 — 준비가 안 된 채로 끌려 들어가지 않도록.

## 모든 문제가 문장으로 나온다

단어와 뜻만 짝지어 외우면, 정작 시험에서 **문장 안에 들어간 그 단어를 못 알아봅니다.**
그래서 "이 단어의 뜻은?" 같이 단어만 덩그러니 보여주는 문제는 두지 않았습니다.

중심은 **빈칸 채우기**입니다. 문장에서 그 단어만 지우고, 거기에 무엇이 들어가야 하는지 묻습니다.

```
빈칸에 알맞은 말을 고르세요

  We should _____ water.
  우리는 물을 아껴야 한다.          ← 해석이 처음부터 보인다

  ① save    ② spend    ③ waste    ④ carry
```

**해석은 문제를 풀기 전부터 보입니다.** 문장을 아직 못 읽는 아이가 찍지 않고 판단할 수 있어야 하기 때문입니다.
정답이 영어 단어라서 해석을 봐도 답이 그대로 드러나지는 않습니다.

실력이 붙으면 부모님 모드 → `해석 미리 보여주기`를 끄면 됩니다. 그러면 답을 고른 뒤에만 해석이 나와서 난이도가 올라갑니다.

> 다만 **`문맥 속 뜻`과 `여러 뜻 구별`은 이 설정과 무관하게 답한 뒤에** 해석이 나옵니다.
> 이 두 유형은 정답이 한국어 뜻이라서, 해석을 미리 보여주면 답이 그대로 노출되어 문제가 성립하지 않습니다.

### 문제 유형 7종

| 유형 | 내용 | 난이도 |
|---|---|---|
| **빈칸 채우기** | 문장의 빈칸에 알맞은 단어 고르기 | ★★ |
| 듣고 빈칸 채우기 | 문장을 듣고 빈칸에 알맞은 단어 고르기 | ★★ |
| 문맥 속 뜻 | 문장에서 색칠된 단어가 여기서 무슨 뜻인지 | ★★ |
| 바꿔 쓰기 | 문맥에 맞게 바꿔 쓸 수 있는 표현(유의어) 고르기 | ★★ |
| **반대말 찾기** | 문장 속 그 단어와 **뜻이 반대인 단어** 고르기 | ★★★ |
| **여러 뜻 구별** | **보기가 전부 그 단어의 뜻.** 문장을 제대로 읽어야만 고를 수 있음 | ★★★ |
| **빈칸에 직접 쓰기** | **보기 없이** 문장의 빈칸에 들어갈 말을 타이핑 | ★★★★ |

오답 보기는 **같은 품사끼리** 뽑습니다. 명사 자리에 동사가 섞여 있으면 문장을 안 읽어도 답이 보이기 때문입니다.

### 유의어·반대말 — 배운 단어끼리 겨루게 한다

`바꿔 쓰기`와 `반대말 찾기`의 **오답 보기는 이미 배운 단어에서 먼저 뽑습니다.**
처음 보는 단어가 보기에 섞이면 아이는 뜻을 견주는 대신 "아는 단어 하나"를 찍습니다.
배운 단어끼리 겨루게 해야 유의어·반대말이 실제로 시험됩니다.
(배운 단어가 아직 적은 초반에는 그 레벨 단어로 채웁니다.)

반대말은 `src/data/antonyms.ts`에 **383쌍, 503개 단어**를 모아 두었습니다.

```
increase ↔ decrease · reduce      accept ↔ refuse · reject · decline
ancient  ↔ modern · recent        rural   ↔ urban
```

여기 실린 반대말은 **전부 우리 어휘 3,286개 안의 단어**입니다. 어휘 밖의 단어를
정답으로 내면 아이가 모르는 것을 찍는 문제가 되기 때문입니다. 검사가 이것을 강제합니다.

- 표제어와 반대말이 모두 어휘 안에 있는지
- 짝이 **양방향**인지 (`increase → decrease`가 있으면 `decrease → increase`도)
- **동의어와 반대말이 겹치지 않는지** — 같은 표현이 '바꿔 쓸 말'이자 '반대말'이면
  둘 다 틀린 문제가 됩니다. 실제로 이 검사가 `employ ↔ hire`(둘은 유의어입니다)를
  잡아냈습니다.

### 영국식·미국식 철자 짝

교육부 기본 어휘 목록에는 `airplane`과 `aeroplane`이 **둘 다** 들어 있습니다.
목록을 그대로 옮겼으니 우리 어휘에도 둘 다 있고, 짚어 주지 않으면 아이는 이 둘을
**서로 다른 단어로** 외웁니다. (베타에서 실제로 딸이 `aeroplane`을 보고
"오타 아니냐"고 물었습니다.)

그래서 단어 카드에서 짝을 알려 줍니다.

```
aeroplane  n.
🇬🇧 영국식 · 짝은 airplane
airplane의 영국식 철자예요. 뜻은 같고, 우리나라 시험에는 보통 airplane이 나와요.
```

`src/data/spelling.ts`에 **20쌍**을 모아 두었습니다 — `colour/color`,
`theatre/theater`, `favourite/favorite`, `defence/defense` 같은 것들입니다.
**우리나라 교과서와 수능은 미국식이 기준**이라, 영국식을 만났을 때 그것을
짚어 주는 쪽에 무게를 두었습니다.

낱말 자체가 다른 것(`petrol`/`gasoline`, `cheque`/`check`)과 영국식에서만
품사로 갈리는 것(`practise` 동사 / `practice` 명사)은 문구를 달리 적습니다.
철자 문제가 아닌데 "철자만 다르다"고 하면 틀린 것을 가르치게 됩니다.

반대말은 뜻이 아니라 **표제어**에 붙입니다. 다의어라도 반대말이 성립하는 것은 보통
대표 뜻 하나뿐이라, 뜻마다 나누면 빈 칸만 늘어납니다. 그래서 다의어는 **대표 뜻을
다룰 때만** 반대말 문제가 나옵니다 — `save(저축하다)`를 놓고 `spend`의 반대라고
물으면 뜻이 어긋나기 때문입니다.

## 다의어는 모든 뜻을 다 시험한다

`save`가 '구하다 / 아끼다 / 저축하다' 세 뜻이면 **한 세션에서 세 문항이 나옵니다.**
한 뜻만 알고 넘어가면 다른 뜻으로 쓰인 문장에서 막히기 때문입니다.

```
① The doctor _____ his life.        → 구하다
② We should _____ water.            → 아끼다
③ I am _____ money for a bike.      → 저축하다
```

그래서 하루 목표가 20단어여도 **문항은 그보다 많습니다.** 중1 20단어면 대략 26문항이 나옵니다.

`여러 뜻 구별` 문제는 여기서 한 발 더 나갑니다. 문장을 주고 **보기를 전부 그 단어의 뜻으로** 채워서,
문장을 제대로 읽지 않으면 고를 수 없게 합니다.

## 한 단어를 두 단계로 — 풀어 보고, 그다음 배운다

문항 하나는 늘 이 순서입니다.

```
① 문제        We should _____ water.        ← 먼저 스스로 답해 본다
              우리는 물을 아껴야 한다.
              ① save  ② spend  ③ waste  ④ carry  ⑤ 모르겠어요

              ↓ 답을 고르면

② 단어 카드   save  [동사]                  ← 그다음에 펼쳐서 배운다
              ✅ 정답!   ✨ 처음 만나는 단어
              오늘 배우는 뜻 · 아끼다, 절약하다
              모든 뜻 3개 + 예문 8개 전부 펼침 · 소리 · 실사용 영상
```

**처음 보는 단어라도 문제를 먼저 냅니다.** 단어 카드를 문제보다 앞에 두면
방금 읽은 것을 그대로 되묻는 꼴이라, 아이는 스스로 떠올려 볼 기회 없이
베껴 답하게 됩니다. 먼저 한 번 씨름해 본 뒤에 답을 보면 훨씬 오래 남습니다.

처음 만나는 단어를 틀리는 것은 당연하므로, 카드에 `✨ 처음 만나는 단어` 표시와
함께 "처음 보는 단어라 몰라도 괜찮아요"라고 적어 둡니다. 틀린 단어는 그날
세션 안에서 다시 나오고, 다음 날 복습에서도 우선순위가 올라갑니다.

## 한 단어를 세 번, 점점 어렵게

4지선다만 반복하면 "아는 것 같은 착각"이 생깁니다. 보기 중에 답이 있어서 알아보기만 하면 되고, 스스로 떠올려 본 적은 없기 때문입니다.

| 라운드 | 단계 | 무엇을 하나 | 주로 나오는 유형 |
|---|---|---|---|
| 1 | **익히기** | 문장 안에서 알아본다 | 빈칸 채우기 · 문맥 속 뜻 |
| 2 | **활용하기** | 뜻을 구별하고, 바꿔 쓰고, 반대말과 견준다 | 여러 뜻 구별 · 바꿔 쓰기 · 반대말 찾기 · 듣고 빈칸 |
| 3 | **떠올리기** | 스스로 꺼낸다 | **빈칸에 직접 쓰기** |

**20단어(≈26문항) × 3라운드 = 약 78문항, 12~15분.**
부모님 모드에서 2회(가볍게) / 3회(표준) / 4회(집중)로 조절할 수 있습니다.

실제 구성 예시 (중1, 새 단어 20개):

```
78문항 — cloze 26 · clozeType 17 · context 11 · synonym 10 · polysemy 8 · listening 6
```

### 설계에 반영한 것

- **한 단어를 연달아 묻지 않습니다.** 라운드마다 순서를 다시 섞어서, 다른 문제를 푸는 사이에 잊었다가 다시 떠올리게 합니다.
- **처음 보는 단어도 문제를 먼저** 냅니다. 대신 1라운드는 가장 쉬운 유형(4지선다 빈칸·문맥 속 뜻)만 나오고, 해석이 함께 보이며, `모르겠어요`를 고를 수 있습니다.
- **모든 4지선다에 "모르겠어요" 보기**가 있습니다. 찍어서 맞히면 앱이 "외웠다"고 잘못 판단해 복습에서 빠져 버립니다.
- **빈칸을 만들 수 없는 예문**(표제어가 문장에 흩어져 있는 경우)에는 빈칸 유형을 내지 않고 뜻·동의어 유형으로 돌립니다. 불규칙 동사 변화표를 넣어 적용률은 99.7%입니다.

## 레벨 시험 — 그 레벨 단어를 모두 맞혀야 올라간다

진도가 90%에 이르면 **레벨 시험 응시 자격**이 생깁니다. 시험을 통과해야 다음 레벨로 올라갑니다.

- 그 레벨의 **모든 단어**가 나옵니다. 137단어면 다의어를 포함해 **160문항 안팎**입니다.
- 빈칸 채우기가 대부분(99%)이고, 빈칸을 못 만드는 문장만 문맥 유형으로 나옵니다.
- **하나도 빠짐없이 맞혀야 통과입니다.**

틀렸다고 떨어뜨리지는 않습니다. 목적이 "빠진 단어를 없애는 것"이지 "떨어뜨리는 것"이 아니라서,
**틀린 문항은 시험이 끝난 뒤 다시 나오고, 전부 맞히면 통과**입니다.

대신 **처음 시도에서 몇 개를 맞혔는지**를 따로 기록합니다. 다시 풀어서 통과했다는 사실이 가려지지 않도록,
부모님 리포트에 `160문항 중 처음에 141개 정답 · 2회 재시도 후 통과`처럼 남습니다.

통과하면 다음 레벨로 올라가고 **보상 요청권**이 하나 생깁니다.

### 같은 단어, 매번 다른 문장

`src/data/entry.ts`의 `exposure()`가 노출 횟수를 인덱스로 돌려 씁니다.
뜻을 바깥 루프, 예문을 안쪽 루프로 돌려서 **뜻이 2개면 번갈아 나옵니다.**

```
save (뜻 3개 × 예문 2~3개)
 0회차 → 구하다      "The doctor saved his life."
 1회차 → 아끼다      "We should save water."
 2회차 → 저축하다    "I am saving money for a bike."
 3회차 → 구하다      "He saved a puppy from the river."   ← 뜻은 같지만 문장이 다름
```

**한 세션 안에서도 라운드마다 문장이 바뀝니다.** 예문 인덱스는 세션을 만들 때
문항마다 못박고, 라운드가 올라갈 때 **1씩만** 더합니다.

```
increase (뜻 2개 × 뜻마다 예문 2개)
 1라운드  늘리다  "Prices increase every year."    반대말 찾기
 2라운드  늘리다  "We must increase our speed."    빈칸 채우기   ← 문장이 바뀐다
 3라운드  늘어나다 "The number increased sharply."  직접 쓰기
```

> 예전에는 화면이 그때그때 `카드의 누적 노출 수 + 라운드`로 계산했습니다.
> 카드는 문제를 풀 때마다 갱신되므로 인덱스가 **2씩** 뛰었고, 나머지 연산 결과가
> 늘 같아져서 **뜻마다 예문이 2개인 다의어는 세 라운드 내내 같은 문장**이
> 나왔습니다. 문장이 고정되면 "단어를 아는 것"과 "그 문장을 외운 것"이
> 구별되지 않습니다.

**틀려서 다시 나올 때도 문장을 바꿉니다.** 세션 끝의 재출제와 레벨 시험의
다시 풀기 모두 예문을 한 칸 넘깁니다. 넘어간 문장으로 빈칸을 만들 수 없으면
유형도 다시 고릅니다.

## 요구권 — 금액이 정해진 보상

갖고 싶은 것을 적어 보내고 매번 협상하는 방식이 아니라, **조건과 금액이 미리
정해진 요구권**입니다. 아이는 얼마가 걸려 있는지 알고 공부하고, 부모는 같은
기준으로 판단하면 됩니다.

| 조건 | 기본 금액 |
|---|---|
| **중학교 레벨** 하나를 끝냄 (중1-1 … 중3-4) | **2만원** |
| **고등학교 레벨** 하나를 끝냄 (고1-1 … 고3-4) | **3만원** |
| **한 달 개근** — 그 달을 하루도 빠짐없이 학습 | **2만원** |

### 금액은 부모님 모드에서 정합니다

위 금액은 **기본값일 뿐이고, 부모님 모드 → `요구권 금액`에서 바꿉니다.**
집집마다 사정이 다른데 숫자를 코드에 박아 두면 쓸 수 없기 때문입니다.

- **0원으로 두면 그 요구권은 아예 생기지 않습니다.** 돈 대신 다른 약속으로
  대신하고 싶을 때 씁니다.
- 화면에 24레벨을 다 끝냈을 때의 합계가 함께 보입니다. 기본값이면
  `2만 × 12 + 3만 × 12 = 60만원`입니다.

### "이번엔 정말 잘했어요" — 만원 더 요구하기

요구권을 신청할 때 아이가 **정해진 금액만큼 한 칸 더** 요구할 수 있습니다(기본 1만원).

```
🎟️ 4만원
   기본 3만원 + 더 요구 1만원

⭐️ 이번엔 정말 잘했어요                    +1만원
   왜 더 받을 만한지 알려 주세요
   "시험을 한 번에 다 맞혔고, 이번 달은 하루도 안 빠졌어요."
```

얼마든 부르는 방식이 아니라 **한 칸만** 올릴 수 있게 했습니다. 매번 금액을
흥정하지 않게 하려는 요구권의 취지를 지키면서도, 아이가 스스로 잘했다고
말할 자리를 만들어 주려는 것입니다. 요구할 수 있는 금액도 부모님이 정하고,
0원으로 두면 버튼 자체가 안 보입니다.

부모님 화면에는 세 가지 길이 있습니다.

| 버튼 | 결과 |
|---|---|
| `4만원 주기` | 아이가 요구한 금액 그대로 |
| `기본 3만원만 주기` | **얹은 금액만 빼고 승인.** 요구를 통째로 거절하지 않아도 됩니다 |
| `다음 기회에` | 보류 |

레벨은 학년당 4개, 모두 24개입니다.

### 한 달 개근

- **목표를 채웠는지가 아니라 그날 학습을 했는지**로 봅니다. 목표까지 요구하면
  몸이 아픈 날 하루에 한 달이 통째로 날아가서 아이가 중간에 포기해 버립니다.
- **그 달이 끝나야 확정**됩니다. 진행 중인 달은 남은 날에 빠질 수 있으니까요.
  마지막 날이 지나면 요구권이 생깁니다.
- 홈 화면에 `이번 달 개근 24/24일`과 남은 날이 표시됩니다. 한 번 빠지면
  "다음 달에 다시 도전해요"로 바뀝니다.
- 윤년 2월(29일)도 맞게 셉니다.

### 흐름

```
아이 ── 레벨 시험 통과 / 한 달 개근 ──▶ 🎟️ 요구권 획득
     ── 홈 화면 `요구권 2장 신청하기 (5만원)` ──▶ 부모님께 신청 (한마디 선택)
부모 ── 부모님 모드 → 보상 요청 ──▶ `주기로 하기` / `다음 기회에` + 한마디
     ── 실제로 준 뒤 ──▶ `줬어요`
```

요구권은 **한 장씩** 신청합니다. 같은 것을 두 번 신청하지 못하도록,
레벨업은 `pendingLevelUps`가 개근은 `claimedMonths`가 원장 역할을 합니다.

금액 규칙과 개근 판정은 화면과 분리된 순수 함수(`src/features/awards.ts`)라
월말·윤년·중복 신청을 테스트로 잡아 둡니다.

## 학습 달력

**하루에 몇 개를 공부했는지 한 달을 한눈에 봅니다.** 홈 화면 아래 `🗓️ 학습 달력`,
부모님 모드에서는 `최근 7일` 카드 안의 `🗓️ 달력으로 보기`로 들어갑니다.

```
        일   월   화   수   목   금   토
                       1    2    3    4
                            15   12   ·
        5    6    7    8    9   10   11
        20   15   8    ·    15   15   15
```

- 칸 안 숫자가 **그날 공부한 단어 수**입니다. 기록이 없으면 `·`.
- 칸 색이 진할수록 많이 한 날입니다. `안 함 / 조금 / 절반 이상 / 목표 달성` 네 단계.
  **목표를 채운 날은 무조건 가장 진하게** 칠합니다. 아이에게는 그게 제일 중요한 신호라서
  단어 수보다 우선합니다.
- 오늘 칸에는 주황 테두리가 붙습니다.
- **칸을 누르면** 그날의 학습 단어 수·정답률·맞음/틀림·학습 시간과 **그날 틀린 단어 목록**이
  아래에 펼쳐집니다.
- `‹` `›` 로 달을 넘깁니다. 기록이 시작된 달보다 앞, 이번 달보다 뒤로는 가지 않습니다.
- 달력 아래 요약: **공부한 날 · 목표 달성 일수 · 공부한 단어 수 · 학습 시간**,
  그리고 평균 정답률 / 그 달 최장 연속 일수 / 가장 많이 한 날.

홈 화면 달력 카드에는 **최근 2주 미리 보기** 막대가 함께 붙어서, 들어가지 않아도
빠진 날이 바로 보입니다.

데이터는 이미 쌓고 있던 `ProfileData.days`(하루 한 건)를 그대로 읽습니다. 달력을 위해
새로 저장하는 것은 없고, **앱을 업데이트하면 지난 기록도 그대로 달력에 나타납니다.**

격자와 월 요약 계산은 화면과 분리된 순수 함수(`src/features/calendar.ts`)라
윤년·월말·요일 밀림을 테스트로 잡아 둡니다.

## 부모님 모드

홈 화면 오른쪽 위 `👨‍👩‍👧 부모님` → PIN 입력.

- **학습 리포트** — 오늘 학습량/정답률/학습 시간/연속 일수, 최근 7일 막대그래프, 레벨 진도,
  **오늘 틀린 단어**와 **누적으로 자주 틀리는 단어**. 아이가 여럿이면 위쪽 탭으로 전환합니다.
- **학습 달력** — 아이별로 한 달 치를 격자로. 어느 날 몇 개 했는지, 어떤 날 빠졌는지 한눈에 봅니다.
- **리포트 공유하기** — 리포트를 텍스트로 만들어 카카오톡·문자로 보냅니다.
- **요구권 승인** — 아이가 올린 요구권을 `주기로 하기` / `다음 기회에`로 판단하고 한마디를 남깁니다. 준 뒤에는 `줬어요`로 마무리 표시.
- **설정** — 알림 시각(오후 6~10시), **하루 새 단어 수**, **하루 복습 수**, 학습 강도(2~4회), **해석 미리 보여주기**, 소리/진동, 학년·레벨 수동 조정, PIN 변경.

### 매일 알림

정해진 시각에 기기 로컬 알림이 뜹니다.

```
📚 오늘의 영단어 학습 리포트
서준 · 오늘 목표 완료! 15개 · 정답률 87% · 5일 연속
지호 · 오늘 아직 학습을 시작하지 않았어요.
```

`목표를 못 채웠을 때만` 옵션을 켜면 미달인 아이만 알립니다.

> **로컬 알림의 한계**: 알림 본문은 예약하는 순간의 상태로 굳습니다. 그래서 앱이 홈 화면에 올 때마다 다시 예약합니다.

## 부모님 폰으로 자동 전송 (서버 없이)

아이 기기와 부모님 폰이 따로일 때, **아이가 학습을 마치면 부모님 폰으로 알림이 바로 갑니다.**
서버를 두지 않고 Expo 푸시 서비스를 중계로 씁니다.

```
아이 기기 ──(HTTPS POST)──▶ Expo 푸시 서버 ──▶ 부모님 폰
```

### 한 번만 하는 연결

1. **부모님 폰**에 같은 앱을 설치 → 부모님 모드 → `부모님 폰 연결` → **이 폰을 부모님 전용으로 쓰기**
2. 폰 이름을 정하고 **연결 링크 보내기** → 카카오톡으로 아이 기기에 전송
3. **아이 기기**에서 그 링크를 한 번 누르면 끝. 링크가 안 열리면 주소를 복사해 붙여넣어도 됩니다.

아이가 여럿이면 기기마다 한 번씩 연결합니다. 같은 링크를 그대로 쓰면 됩니다.
카메라 권한이 필요 없도록 QR 스캔 대신 링크·붙여넣기 방식을 썼습니다.

### 부모님 폰에서 보이는 것

- 학습이 끝나는 **즉시** 알림이 뜹니다 — `📚 서준 학습 리포트 · 오늘 목표 완료! 20개 · 정답률 87%`
- 알림을 지워도 앱 안에 날짜별로 쌓입니다. 틀린 단어까지 그대로 남습니다.
- **밤까지 리포트가 오지 않으면** 부모님 폰이 스스로 `📭 오늘 학습 리포트가 오지 않았어요`를 띄웁니다.
  아이 기기가 꺼져 있으면 아무것도 안 오는데, 그러면 "안 한 건지 앱이 고장 난 건지" 알 수 없기 때문입니다.

### 제약

- **Expo Go에서는 동작하지 않습니다.** EAS로 빌드한 APK여야 푸시 토큰이 나옵니다. `eas init`도 미리 해 두어야 합니다.
- **아이가 앱을 열어 학습을 마쳐야** 전송됩니다. 기기가 꺼져 있으면 못 보냅니다(위의 '안 왔어요' 알림이 이를 메웁니다).
- **리포트 내용이 Expo 서버를 한 번 지나갑니다.** 아래 보안 절에 자세히 적었습니다.
- 부모님이 앱을 지우면 토큰이 죽습니다. 다시 설치하고 연결을 새로 해야 합니다.

### PIN에 대해

PIN은 기기에 평문으로 저장됩니다. **보안 장치가 아니라 아이가 리포트를 지우거나 스스로 보상을 승인하는 것을 막는 실수 방지 장치**입니다.
금융 수준의 보호가 필요하다면 `expo-secure-store`와 서버 인증으로 바꿔야 합니다.

## 단어를 어떻게 골랐나

3단계로 선정했습니다.

1. **기본 뼈대 — 교육부 「기본 어휘 목록」**
   개정 영어과 교육과정 별표에 실린 약 3,000개 어휘가 공식 기준입니다. 교과서는 원칙적으로 이 목록 안에서 나옵니다.
2. **레벨 배정 — 교과서 공통 출현**
   5대 검정 교과서(동아·천재·YBM·미래엔·비상)에 공통으로 나오는 어휘를 학년별로 배치했습니다.
   중1은 기초 동사·형용사, 중3부터 추상 명사, 고2~3은 수능 지문형 어휘로 올라갑니다.
3. **고등 구간 — 수능·모평 기출 빈도 + EBS 연계**
   고1~고3은 평가원 기출 지문 빈도가 높은 어휘와 빈출 구동사·관용구 위주입니다.

각 항목에 `source` 태그(`curriculum` / `textbook` / `csat`)를 달아 두어 나중에 출처별로 걸러낼 수 있습니다.

### 어휘 선정 — 교육부 기본 어휘 목록

`data/official-basic-vocabulary.txt` 가 원본입니다. 2022 개정 영어과 교육과정
(교육부 고시 제2022-33호 [별책 14] [별표 3])의 **기본 어휘 목록 3,000개**를 그대로
옮긴 것으로, 2025년 중1·고1을 시작으로 **2026년 중2·고2**에 적용되는 현행 최신
목록입니다. 그보다 새로운 개정판은 아직 없습니다.

원문의 표시 체계를 그대로 살렸습니다.

| 표시 | 뜻 | 개수 |
|---|---|---|
| `*` | 초등학교 권장 어휘 | 817 |
| `**` | 중학교·고등학교 공통과목 권장 어휘 | 1,214 |
| (없음) | 그 밖의 과목 (고등 수준) | 1,012 |

여기에 `data/extra-vocabulary.txt` 243개를 더합니다. 목록에는 표제어로 없지만
교과서와 시험에 그대로 나오는 것들 — 파생어(`beautiful`, `dangerous`, `important`)와
구동사(`get up`, `take care of`, `look forward to`) 입니다. **총 3,286개.**

### 어떤 단어를 언제 배우는가 — `src/data/plan.ts`

`scripts/build-plan.mjs` 가 위 두 파일을 읽어 배치표를 만듭니다.

1. **난이도 층으로 먼저 나눕니다.** 초등 권장 → 중학 권장 → 고등
2. 같은 층 안에서는 알파벳 순 (같은 층끼리는 난이도 차가 크지 않아, 순서를
   임의로 흔들기보다 원본 문서 순서를 따르는 편이 검증하기 쉽습니다)
3. 전체를 **레벨 24개(학년 6 × 단계 4)** 로 고르게 자릅니다 → **레벨당 137개**

```bash
node scripts/build-plan.mjs > src/data/plan.ts
npm run data:validate
```

배치표를 고쳐 단어가 레벨 사이를 옮겨 다녀도 **학습 기록은 따라옵니다.**
단어 id에 레벨을 넣지 않고 표제어에서만 뽑기 때문입니다(`save` → `save`).

### 왜 학년당 4레벨인가

레벨 시험은 **그 레벨 단어를 하나도 빠짐없이** 맞혀야 통과입니다. 그래서 한
레벨에 단어를 많이 넣을수록 시험이 감당할 수 없이 길어집니다.

| 레벨당 단어 | 시험 문항 | 소요 시간 |
|---|---|---|
| **137개 (현재)** | **160문항 안팎** | **30분** |
| 300개 | 350문항 | 1시간 반 — 무리 |
| 500개 | 590문항 | 사실상 불가능 |

24레벨이면 시험이 30분 선에서 유지되고, **보상 요청 기회도 학년당 네 번**이 됩니다.
한 학년을 떼는 데 두 달이 걸리는데 그동안 보상이 한 번뿐이면 아이 입장에서 너무 멉니다.

레벨 id는 `m1-1` … `h3-4`. 화면에서는 `중1-1`, 설정에서는 `중학교 1학년 레벨 1`.

### 1년에 한 바퀴 — 하루 새 단어 10개

하루 목표를 '전체 단어 수' 하나로 두면, 복습이 자리를 먹어서 새 단어가 하루
서너 개밖에 안 나갑니다. 그러면 3,286개를 도는 데 3년이 걸립니다. 그래서 목표를
둘로 나눴습니다.

| 설정 | 기본값 | 하는 일 |
|---|---|---|
| **하루 새 단어** | 10개 | **진도를 정합니다.** 3,286 ÷ 10 ≈ 329일 |
| **하루 복습** | 10개 | 새 단어 위에 얹힙니다. 밀리면 급한 것부터 |

하루 20단어 × 3라운드 ≈ 78문항 ≈ **13분**. 복습이 밀렸다고 새 단어가 줄지는
않습니다 — 진도가 멈추면 1년이라는 계획이 무너지기 때문입니다.

### 단어를 추가하는 방법

**단어를 파일 어디에 끼워 넣어도 안전합니다.** id를 배열 순서가 아니라 표제어에서
뽑기 때문입니다 (`m1-1-save`). 예전에는 순서로 만들어서(`m1-042`), 중간에 하나만
끼워 넣어도 뒤쪽 id가 전부 밀리며 **이미 쌓인 학습 기록이 엉뚱한 단어에 붙었습니다.**

> 반대로 **표제어의 철자를 고치면 id가 바뀌어 그 단어의 학습 기록이 끊깁니다.**
> 오타 수정은 그 점을 알고 하세요.

**방법 1 — 파일 직접 편집** (몇 개만 추가할 때)

`src/data/levels/m1-2.ts` 의 배열에 추가합니다.

```ts
{ w: 'achieve', p: 'v.', s: [
  { m: '이루다, 달성하다', syn: ['accomplish'], ex: [
    ['She achieved her goal.', '그녀는 목표를 이뤘다.'],
    ['We achieved great results.', '우리는 훌륭한 결과를 달성했다.'],
    ['He achieved success early.', '그는 일찍 성공을 이뤘다.'],
  ]},
]},
```

**방법 2 — CSV로 대량 투입** (수십~수백 개)

스프레드시트로 정리해서 CSV 한 장으로 부어 넣습니다. **레벨 파일을 통째로 덮어쓰므로**
기존 단어까지 CSV에 함께 들어 있어야 합니다.

```bash
node scripts/import-csv.mjs 중1레벨2.csv m1-2 > src/data/levels/m1-2.ts
npm run data:validate
```

CSV 열 순서 (첫 줄은 헤더):

```
word, pos, meaning, synonyms, ex1_en, ex1_ko, ex2_en, ex2_ko, ex3_en, ex3_ko, ex4_en, ex4_ko
```

- 엑셀에서 만들 때는 **CSV UTF-8**로 저장해야 한글이 깨지지 않습니다.
- 뜻에 쉼표가 있으면 큰따옴표로 감쌉니다. 예: `"아끼다, 절약하다"`
- `synonyms`는 `;`로 구분합니다. 예: `rescue;save from`
- **같은 단어를 여러 줄에 적으면 뜻이 여러 개인 것으로 합쳐집니다.** 다의어는 뜻마다 한 줄씩.
- 예문이 3개 미만이면 경고가 뜹니다(파일은 그대로 생성됩니다).

`data/sample-words.csv`에 예시가 들어 있습니다.

`npm run data:validate`가 검사하는 것: id 중복, 같은 레벨 내 표제어 중복, 빈 필드,
단어당 예문 3개 이상, 숙어 분류, **예문에 표제어가 실제로 들어 있는지**, 동의어에 자기 자신이 없는지.

### 데이터가 저장되는 곳

기기 안 AsyncStorage에만 저장됩니다. 밖으로 나가지 않습니다.

- `urivocab:root:v1` — 프로필 목록, 부모 설정, 보상 요청
- `urivocab:data:v1:<프로필 id>` — 그 아이의 카드·일별 기록·답안 로그

아이별로 키를 나눠서, 한 아이가 학습하는 동안 다른 아이 데이터를 건드리지 않습니다.

### 백업 — 파일 한 장으로 통째로

기록이 이 기기 안에만 있으니 **폰을 바꾸거나 앱을 지우면 사라집니다.** 그래서
부모님 모드 → `학습 기록 백업`에서 파일 한 장으로 빼고 넣을 수 있게 했습니다.
카톡으로 자기에게 보내 두거나 드라이브에 올려 두면 그게 백업입니다.

```
가가Voca-백업-2026-07-28.json
  아이 2명 · 학습 기록 · 오답 · 달력 · 요구권까지 전부
```

**되돌리기는 두 단계**입니다. 파일을 고르면 먼저 **무엇이 들어 있는지**(아이 이름 ·
레벨 · 공부한 날 수 · 익힌 단어 수) 보여주고, 그걸 보고 방식을 고릅니다.

| | 언제 | 무슨 일이 일어나나 |
|---|---|---|
| **통째로 되돌리기** | 폰을 바꿨을 때 | 지금 기록을 버리고 백업으로 바꿉니다 |
| **아이만 가져오기** | 아이들 기기를 한 대로 모을 때 | 지금 기록은 두고 아이를 더합니다 |

담지 않는 것이 세 가지 있습니다.

- **부모 PIN** — 파일이 카톡·드라이브를 돌아다니는데 PIN이 적혀 있으면 아이가
  열어 보고 그대로 씁니다. 되돌린 뒤 다시 정하세요.
- **부모님 폰 연결·푸시 토큰** — 새 기기에서 그대로 되살리면 남의 폰으로 리포트를
  쏘거나 죽은 토큰으로 계속 실패합니다.
- **기기 역할(아이용/부모용)** — 그 기기에서 정하는 것이 맞습니다.

`아이만 가져오기`는 **같은 id가 이미 있어도 덮어쓰지 않습니다.** 덮어쓰면 이름만 같은
다른 아이의 1년치가 조용히 사라지기 때문입니다. 새 id로 따로 들어오고, 그 아이의
요구권 기록도 새 id를 따라갑니다.

판단하는 부분은 화면과 분리된 순수 함수(`src/features/backup.ts`)라, 무엇을 담고
무엇을 지키는지를 테스트 26개로 묶어 두었습니다.

## 보안과 개인정보

서버가 없다는 것이 실제로 없애 주는 위험과, 그래도 남는 위험을 나눠서 적습니다.

### 서버가 없어서 사라진 위험

**우리 계정 시스템도, 우리 서버도, 우리 DB도 없습니다.** 그래서 DB 유출, 계정 탈취, 비밀번호 재사용 피해가 원천적으로 없습니다.
아이들 데이터가 한곳에 모여 있지 않아서, 누가 털어 갈 "덩어리"가 존재하지 않습니다.

### 밖으로 나가는 통신은 딱 하나

앞서 "네트워크 호출이 한 줄도 없다"고 적었으나, **부모님 폰 자동 전송을 넣으면서 더 이상 사실이 아닙니다.**

| 언제 | 어디로 | 무엇이 |
|---|---|---|
| 아이가 학습을 마쳤을 때 | Expo 푸시 서버 (`exp.host`) | 아이 이름, 날짜, 학습량, 정답률, 틀린 단어 |

이게 전부입니다. 다른 어떤 통신도 하지 않습니다.
🎬 버튼은 앱이 통신하는 게 아니라 **기기의 브라우저를 여는 것**이라 여기에 해당하지 않습니다.

**연결하지 않으면 이 통신도 없습니다.** 부모님 폰을 연결하지 않거나, 부모님 모드에서 `학습 후 자동 전송`을 끄면
앱은 예전처럼 완전히 오프라인으로 동작합니다.

Expo 푸시 서버는 알림을 배달만 하고 보관하지 않지만, 전달 과정에서 내용이 **제3자 서버를 지나간다**는 점은 사실입니다.
아이 이름 대신 별명을 쓰시면 이 부분이 거의 무의미해집니다.

> **푸시 토큰에 대해**: 부모님 폰의 푸시 토큰을 아는 사람은 그 폰으로 알림을 보낼 수 있습니다.
> 카카오톡으로 링크를 보낼 때 엉뚱한 방에 보내지 않도록만 주의하시면 됩니다.
> 토큰으로 학습 기록을 읽어 갈 수는 없습니다 — 보내기만 가능하고 가져오기는 불가능합니다.

### 그래도 남는 위험

| 위험 | 실제 영향 | 대응 |
|---|---|---|
| **PIN이 평문 저장** | 폰이 루팅/탈옥됐거나 백업 파일에 접근하면 읽을 수 있음 | 아이의 무단 접근을 막는 용도라 현 수준으로 충분. 더 필요하면 `expo-secure-store`로 교체 |
| **기기 분실·도난** | 학습 기록이 그 폰에만 있음. 원격 삭제 불가 | 폰 잠금화면 암호를 걸어 두는 것이 사실상의 방어선 |
| **npm 의존성 (777개)** | 패키지 하나가 오염되면 위험. **서버 없는 앱에서 가장 현실적인 위험** | `npm audit` 정기 확인, Expo SDK 업데이트 |
| **APK 사이드로딩** | "출처를 알 수 없는 앱" 허용 습관 자체가 위험 | 설치 후 그 설정을 다시 끄기 |
| **YouGlish 외부 링크** | 유튜브로 이어져 아이가 다른 영상을 볼 수 있음 | 해킹이 아니라 **콘텐츠 노출** 문제. 원하면 이 버튼을 뺄 수 있음 |

### 저장되는 개인정보

기기 안에만 저장되고 밖으로 나가지 않습니다.

- 저장하는 것: 아이 이름(별명 가능), 이모지, 학년, 학습 기록, 오답 단어, 보상 요청 문구, 부모 PIN
- **저장하지 않는 것: 전화번호, 이메일, 주소, 사진, 위치, 결제 정보**

유출되더라도 피해가 크지 않은 수준입니다. 걱정되시면 **이름 대신 별명**을 쓰시면 됩니다.

### 현재 알려진 취약점

`npm audit` 기준 moderate 11건이며, 근본 원인은 **한 가지**입니다.

```
uuid 7.0.3 — buffer 경계 검사 누락 (GHSA-w5hq-g745-h8pq)
경로: expo-splash-screen → @expo/config-plugins → xcode → uuid
```

`xcode`는 Xcode 프로젝트 파일을 다루는 **빌드 도구**라서 앱에 포함되지 않고 실행되지도 않습니다.
Expo가 상위 패키지를 갱신하면 자연히 해소됩니다.

## 알아 두면 좋은 제약

- **부모님 폰 전송은 Expo Go에서 안 됩니다.** EAS로 빌드한 APK·TestFlight 앱이어야
  푸시 토큰이 나옵니다. 연결하지 않으면 리포트 공유하기(카카오톡·문자)로 대신할 수 있습니다.
- **영상은 YouGlish 링크**입니다. 앱이 영상을 직접 보유하지 않고 외부 브라우저로 넘깁니다.
  자체 영상을 만들어 올리는 것은 제작비와 저작권 문제가 커서 제외했습니다.
- **발음은 기기 TTS**를 씁니다. 기기에 영어 음성이 없으면 조용히 넘어가고, 학습은 계속됩니다.
- **빈칸 채우기는 규칙 변화형 + 불규칙 변화표**로 표제어를 찾습니다. 예문 10,047개 중
  29개(0.3%)는 표제어가 문장에 흩어져 있어(`take ... into account`) 빈칸을 못 만듭니다.
  그때는 다른 게임이 배정되므로 학습에 지장은 없습니다.
- 데이터는 손으로 검수하고 자동 검사(`npm run data:validate`)까지 통과했지만,
  **예문 10,047개 전부가 완벽하다고 보장할 수는 없습니다.** 어색한 뜻이나 예문을
  발견하면 해당 `src/data/levels/*.ts`에서 바로 고치면 됩니다.
  표제어 철자만 건드리지 않으면 이미 쌓인 학습 기록은 그대로 유지됩니다.

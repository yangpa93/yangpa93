# 0장. git이 무엇이고 왜 필요한가

## 소스가 있는 곳은 두 군데입니다

```
   ┌─────────────────┐            ┌─────────────────┐
   │     깃허브       │            │   내 컴퓨터      │
   │   (github.com)  │            │  C:\MyDirectory │
   │                 │            │                 │
   │  제가 여기에     │  ←──────→  │  회원님이 여기서 │
   │  고친 것을 올림  │            │  빌드하심        │
   └─────────────────┘            └─────────────────┘
```

둘은 **자동으로 같아지지 않습니다.** 제가 깃허브에 올려도 회원님 컴퓨터는 그대로
입니다. 명령을 쳐서 가져오셔야 합니다. 그 명령이 `fetch` 와 `pull` 입니다.

반대로 회원님 컴퓨터에서 뭔가 고쳐도 깃허브는 그대로입니다. 올리는 명령이
`push` 입니다.

## 내 컴퓨터 안에도 칸이 셋입니다

이게 git이 헷갈리는 가장 큰 이유입니다. **파일을 고쳤다고 저장된 게 아닙니다.**

```
  ① 작업 폴더        ② 대기실         ③ 내 저장소       ④ 깃허브
  (지금 보이는 파일)   (staging)      (.git 폴더)      (github.com)

       파일 고침
          │
          │  git add       →  git commit    →  git push
          └──────────────────────────────────────────────→
```

| 칸 | 무엇인가 | 여기 있는 것은 |
|---|---|---|
| ① 작업 폴더 | 지금 눈에 보이는 파일들 | 폴더를 지우면 사라집니다 |
| ② 대기실 | "이번에 저장할 것"으로 골라 둔 것 | 아직 아무 데도 안 남았습니다 |
| ③ 내 저장소 | 못박힌 이력. `.git` 이라는 숨은 폴더 | 폴더를 지우면 같이 사라집니다 |
| ④ 깃허브 | 인터넷에 있는 진짜 보관소 | 컴퓨터가 망가져도 남습니다 |

**`git push` 를 해야 비로소 안전해집니다.** ③까지만 하면 폴더를 지울 때 같이
사라집니다.

## 브랜치는 '작업 줄기'입니다

같은 저장소 안에 여러 줄기가 나란히 있을 수 있습니다.

```
main ──●──●──●                     ← README만 있는 줄기. vocab-app 폴더가 없습니다
        \
         ●──●──●──●                ← 앱을 처음 만든 줄기
                   \
                    ●──●──●──●     ← 지금 작업 중인 줄기
```

**회원님 폴더는 한 번에 한 줄기만 볼 수 있습니다.** 제가 새 줄기에 올렸는데
회원님이 옛 줄기를 보고 있으면, 아무리 `pull` 해도 고친 것이 안 들어옵니다.

> **실제로 겪은 일**
> 제가 앱 이름을 `곰탱이보카` 로 바꿔 `claude/voca-meaning-review-kzo48f` 에
> 올렸는데, 회원님 폴더는 `claude/english-vocab-learning-app-pfy9yg` 를 보고
> 있었습니다. 그래서 빌드해도 계속 `가가_Voca` 가 나왔습니다.
> 두 줄기는 **54개 커밋**만큼 벌어져 있었습니다.

## 커밋은 '저장 지점'입니다

`cdd16e1` 같은 일곱 자리 번호가 붙습니다. 이 번호로 **정확히 어느 시점인지**
가릴 수 있습니다. 제가 "`cdd16e1` 로 받으세요"라고 하는 것은 "이 저장 지점까지
가져오세요"라는 뜻입니다.

# 1장. 명령어 사전

## 가져오는 쪽

| 명령 | 무엇을 하나 | 언제 쓰나 |
|---|---|---|
| `git clone -b <브랜치> <주소>` | 저장소를 **처음** 통째로 받아 옵니다 | 폴더가 아예 없을 때. 딱 한 번 |
| `git fetch origin <브랜치>` | 깃허브의 최신 내용을 **받아만 둡니다.** 내 파일은 안 바뀝니다 | 뭐가 올라왔는지 확인만 하고 싶을 때 |
| `git pull origin <브랜치>` | 받아서 **내 파일에 합칩니다** (`fetch` + 합치기) | 같은 줄기의 최신을 가져올 때. **가장 자주 씁니다** |
| `git checkout <브랜치>` | **다른 줄기로 옮겨 갑니다** | 브랜치가 바뀌었을 때 |

### `fetch` 와 `pull` 이 어떻게 다른가

```
git fetch     깃허브 → 내 저장소(③)까지만.        내 눈에 보이는 파일은 그대로
git pull      깃허브 → 내 저장소 → 작업 폴더(①).  내 파일이 실제로 바뀜
```

`pull` 은 `fetch` 를 포함합니다. 그래서 보통은 `pull` 하나면 됩니다.
`fetch` 를 따로 쓰는 때는 **"올라온 게 있는지 보기만"** 할 때입니다.

```powershell
git fetch origin claude/voca-meaning-review-kzo48f
git log --oneline -1 origin/claude/voca-meaning-review-kzo48f   # 깃허브 쪽 최신
git log --oneline -1                                            # 내 쪽 최신
```
두 줄의 번호가 다르면 받아올 게 있다는 뜻입니다.

## 올리는 쪽

| 명령 | 무엇을 하나 |
|---|---|
| `git add <파일>` | 그 파일을 **대기실(②)** 에 올립니다 |
| `git commit -m "메모"` | 대기실에 있는 것을 **내 저장소(③)** 에 못박습니다 |
| `git push origin <브랜치>` | 내 저장소를 **깃허브(④)** 로 올려 보냅니다 |

`add` 와 `commit` 이 나뉜 이유는, 고친 것 중 **일부만 골라** 저장할 수 있게
하려는 것입니다. 파일 하나면 굳이 나눌 일이 없어 보이지만 git은 늘 두 칸을
거칩니다.

`git add .` 은 "고친 것 **전부**"라는 뜻입니다. 점 하나가 '여기 폴더 전부'입니다.

## 살펴보는 쪽 (아무것도 안 바꿉니다. 마음껏 쓰세요)

| 명령 | 무엇을 보여주나 |
|---|---|
| `git status` | 지금 상태 요약. **막히면 제일 먼저 이걸 보세요** |
| `git log --oneline -1` | 내가 지금 어느 저장 지점에 있는지 |
| `git log --oneline -5` | 최근 다섯 개 |
| `git branch --show-current` | 내가 지금 어느 줄기에 있는지 |
| `git branch -r` | 깃허브에 어떤 줄기들이 있는지 |
| `git remote -v` | `origin` 이 어느 주소를 가리키는지 |

## 되돌리는 쪽 (조심)

| 명령 | 무엇을 하나 | 위험도 |
|---|---|---|
| `git checkout -- <파일>` | 그 파일 하나를 저장소 원본으로 되돌립니다 | 그 파일의 내 수정만 사라짐 |
| `git reset --hard origin/<브랜치>` | **내 폴더를 깃허브와 똑같이 강제로 맞춥니다** | 내 수정이 전부 사라짐 |

`reset --hard` 는 되돌릴 수 없습니다. 다만 **회원님은 코드를 직접 고치지
않으시므로** 잃을 것이 `app.json` 하나뿐이고, 그건 아래 절차에서 미리 챙깁니다.
꼬였을 때 가장 확실한 길입니다.

## `origin` 이 무엇인가

깃허브 주소의 **별명**입니다. 매번 `https://github.com/yangpa93/yangpa93.git` 을
치지 않으려고 git이 붙여 둔 이름입니다.

```powershell
git remote -v     # origin 이 어디를 가리키는지 확인
```

그래서 `git push origin <브랜치>` 는 **"깃허브의 그 줄기로 올려라"** 입니다.

# 2장. 브랜치 이름 알아내는 법

**세 가지 길이 있습니다. 아무거나 편한 것으로.**

## 방법 1 — 제게 물어보기 (가장 확실)

제가 작업을 끝낼 때마다 **브랜치 이름과 커밋 번호**를 알려 드립니다. 그대로
쓰시면 됩니다. 못 들으셨으면 그냥 "브랜치 이름이 뭔가요?" 하고 물어 주세요.

## 방법 2 — 깃허브에서 눈으로 보기

1. https://github.com/yangpa93/yangpa93 로 갑니다
2. 왼쪽 위 **`main ▾`** 라고 쓰인 단추를 누릅니다
3. 줄기 목록이 펼쳐집니다. **맨 위에 있는 것이 가장 최근에 손댄 줄기**입니다

또는 https://github.com/yangpa93/yangpa93/branches 로 바로 가시면 목록이
`Updated 2 hours ago` 같은 시각과 함께 나옵니다.

## 방법 3 — 명령으로 보기

```powershell
cd C:\MyDirectory\gagavoca\yangpa93\vocab-app

# 깃허브 소식 받아 오기 (파일은 안 바뀝니다)
git fetch origin

# 최근에 손댄 순서로 줄기 목록
git branch -r --sort=-committerdate
```

이렇게 나옵니다. **맨 위가 가장 최근**입니다.

```
  origin/claude/voca-meaning-review-kzo48f      ← 지금 작업 중인 줄기
  origin/claude/english-vocab-learning-app-pfy9yg
  origin/claude/voca-meaning-review-2l1ybj
  origin/main
```

앞의 `origin/` 은 "깃허브 쪽"이라는 표시입니다. 명령에 쓸 때는 **빼고** 씁니다.

```powershell
git checkout claude/voca-meaning-review-kzo48f     # origin/ 없이
```

## 지금 내가 어느 줄기에 있나

```powershell
git branch --show-current
```

이것과 제가 알려 드린 이름이 **글자 하나까지 같아야** 합니다.

## 1단계 — 고쳐 달라고 할 때 준비할 것

세 가지면 됩니다. **다 모르셔도 괜찮습니다.**

### 1-1. 무엇이 이상한가

| 이렇게 주시면 | 왜 좋은가 |
|---|---|
| **어느 화면**에서 그랬는지 | 화면 이름만 알아도 파일이 좁혀집니다 |
| **무엇을 눌렀는지** | 같은 화면이라도 누른 것에 따라 다른 코드가 돕니다 |
| **무엇을 기대했고 실제로 무엇이 나왔는지** | "이상하다"보다 "A가 나와야 하는데 B가 나왔다"가 빠릅니다 |
| **화면 사진** | 제일 확실합니다 |

### 1-2. 어느 빌드에서 그랬는지

**아이가 직접 보낼 수 있습니다.**

```
아이 폰 → ⚙️ 설정 → 💬 이상한 점 알려주기 → 알려주기
```

이런 글이 자동으로 만들어집니다. 카카오톡으로 자기에게 보내 두고 붙여 주세요.

```
[곰탱이보카] 이상한 점 알려주기

어느 화면에서 그랬나요?
무엇을 눌렀나요?
어떻게 되기를 바랐나요?

── 아래는 지우지 말아 주세요 ──
앱: 곰탱이보카 0.9.0 (3) · android
보낸 때: 2026. 7. 29. 오후 3:12:05
```

**맨 아래 두 줄이 중요합니다.** 고쳐 드렸는데 아직 옛 앱을 쓰고 있는 경우가
흔합니다. 그 번호를 보면 바로 압니다.

홈 화면 위 `📱 0.9.0 (3) · android` 칩이나 `⚙️ 설정` 맨 아래 줄을 사진으로
찍어 주셔도 같습니다.

### 1-3. 기록 지켜 두기 (권합니다)

```
아이 폰 → ⚙️ 설정 → 💾 공부 기록 지키기 → 백업 · 되돌리기 → 백업 파일 내보내기
```

## 4단계 — 소스 받기

### 4-1. 브랜치가 같을 때 (가장 흔합니다)

```powershell
cd C:\MyDirectory\gagavoca\yangpa93\vocab-app

Copy-Item app.json app.json.bak -Force
git checkout -- app.json package.json package-lock.json
git pull origin <브랜치이름>
node scripts/relink-eas.mjs
npm install
```

### 4-2. 브랜치가 바뀌었을 때

```powershell
cd C:\MyDirectory\gagavoca\yangpa93\vocab-app

Copy-Item app.json app.json.bak -Force
git checkout -- app.json package.json package-lock.json
git fetch origin <새브랜치이름>
git checkout <새브랜치이름>
git pull origin <새브랜치이름>
node scripts/relink-eas.mjs
npm install
```

> `checkout` 뒤에 `pull` 을 한 번 더 하는 이유 — 그 줄기를 예전에 받아 둔 적이
> 있으면 `checkout` 이 **옛 시점**으로 데려갑니다. `pull` 이 최신까지 끌어옵니다.

### 4-3. 처음부터 새로 받을 때

폴더가 꼬였을 때 가장 확실합니다. **기존 폴더는 지우지 말고 이름만 바꿔 두세요.**

```powershell
cd C:\MyDirectory\gagavoca
Rename-Item yangpa93 yangpa93-old

git clone -b <브랜치이름> https://github.com/yangpa93/yangpa93.git
cd yangpa93\vocab-app
npm install

Copy-Item ..\..\yangpa93-old\vocab-app\app.json app.json.bak
node scripts/relink-eas.mjs
```

> **`-b <브랜치이름>` 을 절대 빼지 마세요.** 안 붙이면 `main` 을 받는데, 거기에는
> README만 있고 `vocab-app` 폴더 자체가 없습니다.

### 각 명령이 무슨 일을 하나

| 명령 | 하는 일 | 왜 필요한가 |
|---|---|---|
| `Copy-Item app.json app.json.bak -Force` | `app.json` 을 복사해 둡니다 | 이 파일에 **내 PC에만 있는 EAS 프로젝트 ID** 가 있습니다. 저장소에는 없어서 다음 줄에서 지워집니다. `-Force` 는 이미 있는 `.bak` 을 덮어쓰라는 뜻 |
| `git checkout -- <파일들>` | 그 파일들을 저장소 원본으로 되돌립니다 | 손댄 파일이 있으면 git이 "덮어쓰면 잃어버립니다" 하며 멈춥니다. 위에서 복사해 뒀으니 안전 |
| `git pull origin <브랜치>` | 최신을 받아 내 파일에 합칩니다 | 제가 고친 것이 이때 들어옵니다 |
| `git fetch` + `git checkout` | 다른 줄기를 받아 그리로 옮깁니다 | `pull` 은 같은 줄기 안에서만 씁니다 |
| `node scripts/relink-eas.mjs` | `app.json.bak` 에서 EAS 연결 정보만 뽑아 새 `app.json` 에 얹습니다 | 새 `app.json` 에는 최신 설정(이름·아이콘·권한)이 있고 거기에 연결 정보만 되살리는 것. 손으로 고치다 깨뜨릴 일이 없습니다 |
| `npm install` | 필요한 꾸러미를 맞춥니다 | 새 기능을 넣으며 꾸러미가 늘었을 수 있습니다 |

## 8단계 — `app.json` 을 깃허브에 올리기

**앱을 쓰는 데는 필요 없습니다.** 다음번을 편하게 하려는 것입니다.

```powershell
git add app.json
git commit -m "eas 프로젝트 연결"
git push origin <브랜치이름>
```

### 왜 하는가

`eas init` 이 만든 프로젝트 ID 는 **빌드할 때 APK 안에 박힙니다.** 그래서 이미 깐
앱은 이걸 하든 말든 잘 돌아갑니다.

문제는 **폴더를 지우거나 PC를 바꿨을 때**입니다.

```
올려 두면    새로 clone → 프로젝트 ID 가 딸려 온다 → 바로 빌드 ✅

안 올리면    새로 clone → ID 가 없다 → eas init 다시
             → 잘못하면 새 프로젝트가 생김 → ID 가 달라짐
             → 부모님 폰 연결이 끊겨 다시 연결해야 함 ❌
```

한 번 올려 두면 그 뒤로는 4단계의 `Copy-Item` · `relink-eas` 도 필요 없어지고
`git pull` 한 줄로 끝납니다.

### 안전한가

프로젝트 ID 는 **비밀번호가 아닙니다.** 어차피 APK 안에 들어가 누구나 꺼내 볼 수
있는 값입니다. Expo 공식 문서도 올리라고 안내합니다.

**부모 PIN·아이 이름·학습 기록은 깃허브에 올라가지 않습니다.** 전부 폰 안에만
있고 `app.json` 과 무관합니다.

## 먼저 이 네 줄을 보세요

```powershell
git status
```

마지막 두 줄의 번호를 견주면 대부분 원인이 드러납니다.

| 마지막 두 줄 | 뜻 |
|---|---|
| 번호가 같다 | 이미 최신입니다. 받을 게 없습니다 |
| 다르다 | 받아올 게 있는데 안 합쳐진 것입니다 → `git pull origin <브랜치>` |
| 오류가 난다 | 브랜치 이름이 틀렸거나 인터넷 문제입니다 |

## 꼬였을 때 확실하게 맞추기

```powershell
cd C:\MyDirectory\gagavoca\yangpa93\vocab-app

Copy-Item app.json app.json.bak -Force
git fetch origin <브랜치이름>
git reset --hard origin/<브랜치이름>
node scripts/relink-eas.mjs
npm install

git log --oneline -1        # 제가 알려 드린 번호가 나와야 합니다
```

`reset --hard` 는 **내 폴더를 깃허브와 똑같이 강제로 맞춥니다.** 내가 손댄 것은
되돌릴 수 없게 사라지지만, 회원님은 코드를 직접 고치지 않으시고 `app.json` 은
첫 줄에서 챙겨 뒀으니 잃을 것이 없습니다.

## 자주 나오는 오류

| 화면에 나오는 말 | 뜻 | 어떻게 |
|---|---|---|
| `Your local changes would be overwritten` | 손댄 파일이 있어 덮을 수 없다 | 파일 이름이 같이 나옵니다. `git checkout -- 그파일` 후 다시 |
| `divergent branches` / `have diverged` | 내 쪽과 깃허브 쪽이 갈라졌다 | 위의 `reset --hard` 로 |
| `'head' 용어가 ... 인식되지 않습니다` | 리눅스 명령을 PowerShell에서 썼다 | [부록 A](#부록-a--리눅스--powershell-명령-대응) |
| `'eas' 용어가 ... 인식되지 않습니다` | `eas` 를 못 찾는다 | `npx eas-cli@latest ...` 로 쓰세요 |
| `프로젝트 ID가 없습니다` (앱 안에서) | `eas init` 없이 빌드했다 | 5단계 ③ |
| `vocab-app 폴더가 없다` | `-b <브랜치>` 없이 clone 했다 | 4-3 다시 |
| `Generate a new Android Keystore?` 를 두 번째로 물음 | 열쇠를 못 찾고 있다 | **`y` 하지 마시고** 알려 주세요 |
| 빌드는 됐는데 고친 게 안 보임 | 옛 브랜치·옛 커밋에서 빌드했다 | 3단계와 5단계 ① |

풀리지 않으면 **화면에 나온 글을 요약하지 마시고 통째로** 붙여 주세요.
어느 줄이 원인인지는 제가 봅니다.

# 부록 A — 리눅스 ↔ PowerShell 명령 대응

제가 실수로 리눅스 명령을 드릴 때가 있습니다.

| 리눅스 | PowerShell |
|---|---|
| `head -4 파일` | `Get-Content 파일 -TotalCount 4` |
| `cat 파일` | `Get-Content 파일` |
| `grep 무엇 파일` | `Select-String -Path 파일 -Pattern 무엇` |
| `cp a b` | `Copy-Item a b` |
| `mv a b` | `Rename-Item a b` |
| `rm -rf 폴더` | `Remove-Item 폴더 -Recurse -Force` |
| `ls` | `Get-ChildItem` (`ls` 도 됩니다) |

`git` · `npm` · `npx` · `node` 는 윈도우에서도 **그대로**입니다.

# 부록 B — 이 문서의 말

| 말 | 뜻 |
|---|---|
| **저장소(repository)** | 소스와 그 이력이 통째로 담긴 곳. 깃허브에 있는 것과 내 컴퓨터에 있는 것이 짝을 이룹니다 |
| **브랜치(branch)** | 저장소 안의 작업 줄기 |
| **커밋(commit)** | 저장 지점. `cdd16e1` 같은 번호가 붙습니다 |
| **origin** | 깃허브 주소의 별명 |
| **clone** | 처음 통째로 받아 오기 |
| **fetch** | 받아만 두기. 내 파일은 안 바뀜 |
| **pull** | 받아서 내 파일에 합치기 |
| **push** | 내 커밋을 깃허브로 올리기 |
| **EAS** | Expo가 대신 앱을 컴파일해 주는 서비스. 덕분에 안드로이드 SDK를 깔지 않아도 됩니다 |
| **키스토어(keystore)** | 앱에 도장을 찍는 열쇠. 바뀌면 안드로이드가 **다른 앱**으로 봅니다 |
| **APK** | 안드로이드 앱 설치 파일 |

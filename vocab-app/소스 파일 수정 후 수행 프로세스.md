# 소스 파일 수정 후 수행 프로세스

앱에서 이상한 점을 발견했을 때부터, 고쳐진 APK를 폰에 다시 까는 데까지의 전 과정입니다.

컴퓨터는 **윈도우 PowerShell** 기준으로 적었습니다. 맥·리눅스를 쓰신다면 맨 뒤
[부록 B](#부록-b--맥리눅스를-쓰신다면)를 보세요.

---

## 한 장 요약

익숙해지신 뒤에는 이 여섯 줄이면 됩니다.

```powershell
cd C:\MyDirectory\gagavoca\yangpa93\vocab-app
Copy-Item app.json app.json.bak                 # 내 PC에만 있는 EAS 연결 정보 보관
git checkout -- app.json package.json package-lock.json
git pull origin <브랜치이름>                     # 브랜치가 바뀌었으면 4-2로
node scripts/relink-eas.mjs                     # 보관해 둔 연결 정보 다시 얹기
npm install
npx eas-cli@latest build --platform android --profile preview
```

**`<브랜치이름>` 은 매번 제게 물어보세요.** 작업할 때마다 달라질 수 있고, 브랜치를
잘못 잡으면 고친 것이 하나도 안 들어옵니다. 실제로 한 번 그랬습니다 — 앱 이름을
바꿨는데 옛 브랜치에서 빌드해서 계속 옛 이름이 나왔습니다.

## 1단계 — 고쳐 달라고 할 때 준비할 것

세 가지만 알려 주시면 됩니다. **다 모르셔도 괜찮습니다.** 아는 만큼만 주세요.

### 1-1. 무엇이 이상한가

| 이렇게 주시면 | 왜 좋은가 |
|---|---|
| **어느 화면**에서 그랬는지 | 화면 이름(단어장, 오답 노트, 부모님 모드…)만 알아도 파일이 좁혀집니다 |
| **무엇을 눌렀는지** | 같은 화면이라도 누른 것에 따라 다른 코드가 돕니다 |
| **무엇을 기대했고 실제로는 무엇이 나왔는지** | "이상하다"보다 "A가 나와야 하는데 B가 나왔다"가 훨씬 빠릅니다 |
| **화면 사진** | 제일 확실합니다. 글로 못 쓰는 것도 사진은 다 담습니다 |

### 1-2. 어느 빌드에서 그랬는지

앱이 자동으로 알려 주는 길이 있습니다. **아이가 직접 보낼 수 있습니다.**

```
아이 폰 → ⚙️ 설정 → 💬 이상한 점 알려주기 → 알려주기
```

부모님 설정에도 같은 카드가 있습니다.

그러면 이런 글이 자동으로 만들어집니다. 카카오톡으로 자기에게 보내 두고 제게
붙여 주세요.

```
[곰탱이보카] 이상한 점 알려주기

어느 화면에서 그랬나요?


무엇을 눌렀나요?


어떻게 되기를 바랐나요?


── 아래는 지우지 말아 주세요 ──
앱: 곰탱이보카 0.9.0 (3) · android
보낸 때: 2026. 7. 29. 오후 3:12:05
```

**맨 아래 세 줄이 중요합니다.** 고쳐서 새 APK를 드렸는데 아이가 아직 옛 앱을 쓰고
있는 경우가 흔합니다. 그 번호를 보면 바로 압니다.

아이 홈 화면 위쪽의 `📱 0.9.0 (3) · android` 칩이나, `⚙️ 설정` 맨 아래의
`곰탱이보카 0.9.0 (3) · android` 줄을 사진으로 찍어 주셔도 같습니다.

### 1-3. 기록을 지켜 두기 (권합니다)

제가 데이터 구조를 건드려야 하는 고침이면, 아주 드물게 기록이 영향을 받을 수
있습니다. 큰일 나기 전에 빼 두세요.

```
아이 폰 → ⚙️ 설정 → 💾 공부 기록 지키기 → 백업 · 되돌리기 → 백업 파일 내보내기
```

나온 파일을 카카오톡으로 자기에게 보내 두거나 드라이브에 올려 두시면 됩니다.
**아이가 둘이면 각 폰에서 따로 해야 합니다.** 기록은 그 폰 안에만 있습니다.

## 3단계 — 브랜치 확인 (제일 중요)

**빌드하기 전에 반드시 확인하세요.** 여기서 어긋나면 뒤의 모든 단계가 헛일입니다.

지금 내 폴더가 어느 브랜치인지:

```powershell
cd C:\MyDirectory\gagavoca\yangpa93\vocab-app
git branch --show-current
```

제가 알려 드린 브랜치와 **글자 하나까지 같은지** 보세요.

- **같다** → 4-1 로
- **다르다** → 4-2 로
- **폴더가 아예 없다** → 4-3 로

> ### 브랜치가 무엇인가요
>
> 같은 저장소 안에 든 **서로 다른 작업 줄기**입니다. 저는 작업 덩어리마다 새
> 줄기를 만들어 거기에 올립니다. 회원님 폴더는 한 번에 한 줄기만 볼 수 있어서,
> 제가 올린 줄기로 옮겨 오셔야 고친 것이 보입니다.
>
> 실제로 이런 일이 있었습니다 — 제가 앱 이름을 `곰탱이보카` 로 바꿔서
> `claude/voca-meaning-review-kzo48f` 에 올렸는데, 회원님 폴더는
> `claude/english-vocab-learning-app-pfy9yg` 를 보고 있었습니다. 그래서 빌드해도
> 계속 `가가_Voca` 가 나왔습니다. 두 줄기가 **54개 커밋**만큼 벌어져 있었습니다.

## 4단계 — 소스 받기

### 4-1. 브랜치가 같을 때 (가장 흔합니다)

```powershell
cd C:\MyDirectory\gagavoca\yangpa93\vocab-app

Copy-Item app.json app.json.bak
git checkout -- app.json package.json package-lock.json
git pull origin <브랜치이름>
node scripts/relink-eas.mjs
npm install
```

### 4-2. 브랜치가 바뀌었을 때

```powershell
cd C:\MyDirectory\gagavoca\yangpa93\vocab-app

Copy-Item app.json app.json.bak
git checkout -- app.json package.json package-lock.json
git fetch origin <새브랜치이름>
git checkout <새브랜치이름>
node scripts/relink-eas.mjs
npm install
```

### 4-3. 처음부터 새로 받을 때

폴더가 꼬였을 때 가장 확실한 길입니다. **기존 폴더는 지우지 말고 이름만 바꿔
두세요** — 뭔가 잘못되면 되돌아갈 자리가 됩니다.

```powershell
cd C:\MyDirectory\gagavoca
Rename-Item yangpa93 yangpa93-old

git clone -b <브랜치이름> https://github.com/yangpa93/yangpa93.git
cd yangpa93\vocab-app
npm install

# 옛 폴더에서 EAS 연결 정보 가져오기
Copy-Item ..\..\yangpa93-old\vocab-app\app.json app.json.bak
node scripts/relink-eas.mjs
```

> **`-b <브랜치이름>` 을 절대 빼지 마세요.** 안 붙이면 `main` 을 받는데, 거기에는
> README만 있고 `vocab-app` 폴더 자체가 없습니다.

### 이 명령들이 각각 무슨 일을 하나

| 명령 | 하는 일 | 왜 필요한가 |
|---|---|---|
| `Copy-Item app.json app.json.bak` | `app.json` 을 복사해 둡니다 | 이 파일에는 **회원님 PC에만 있는 EAS 프로젝트 ID** 가 들어 있습니다. 저장소에는 없어서 다음 줄에서 지워집니다 |
| `git checkout -- 파일들` | 그 파일들을 저장소 원본으로 되돌립니다 | 손댄 파일이 남아 있으면 git이 "덮어쓰면 잃어버립니다" 하며 멈춥니다. 위에서 복사해 뒀으니 안전합니다 |
| `git pull origin <브랜치>` | 그 브랜치의 최신 내용을 받아 지금 폴더에 합칩니다 | 제가 고친 것이 이때 들어옵니다 |
| `git fetch` + `git checkout <브랜치>` | 다른 줄기를 받아서 그리로 옮겨 갑니다 | 브랜치가 바뀐 경우. `pull` 은 같은 줄기 안에서만 씁니다 |
| `node scripts/relink-eas.mjs` | `app.json.bak` 에서 EAS 연결 정보만 뽑아 새 `app.json` 에 얹습니다 | 새로 받은 `app.json` 에는 최신 설정(이름·아이콘·권한)이 들어 있고, 거기에 연결 정보만 되살리는 것입니다. 손으로 고치다 파일을 깨뜨릴 일이 없습니다 |
| `npm install` | 필요한 패키지를 맞춥니다 | 제가 새 기능을 넣으면서 패키지가 늘었을 수 있습니다 |

## 8단계 — `app.json` 을 저장소에 올리기

**이건 앱을 쓰는 데는 필요 없습니다.** 다음번을 편하게 하려는 것입니다.

```powershell
git add app.json
git commit -m "eas 프로젝트 연결"
git push origin <브랜치이름>
```

### 왜 하는가

`eas init` 이 만든 프로젝트 ID 는 **빌드할 때 APK 안에 박힙니다.** 그래서 이미 깐
앱은 이걸 하든 말든 잘 돌아갑니다.

문제는 **폴더를 지우거나 PC를 바꿨을 때**입니다.

```
저장소에 올려 두면    새로 clone → 프로젝트 ID 가 딸려 온다 → 바로 빌드 ✅

안 올려 두면          새로 clone → ID 가 없다 → eas init 다시
                      → 잘못하면 새 프로젝트가 만들어짐 → ID 가 달라짐
                      → 부모님 폰 연결이 끊겨 다시 연결해야 함 ❌
```

한 번 올려 두면 그 뒤로는 4단계의 `Copy-Item` · `relink-eas` 를 안 하셔도 되고,
`git pull` 한 줄로 끝납니다.

### 세 명령이 각각 무슨 일을 하나

git은 **세 칸**을 오갑니다. 세 명령이 그 사이를 한 칸씩 옮기는 것입니다.

```
   내 폴더            대기실            내 저장소          깃허브
  (파일 고침)  →  git add  →  git commit  →  git push  →
```

| 명령 | 하는 일 | 안 하면 |
|---|---|---|
| `git add app.json` | "이 파일을 저장할 것"이라고 **대기실에 올립니다** | 다음 `commit` 이 이 파일을 못 봅니다 |
| `git commit -m "..."` | 대기실에 있는 것을 **내 컴퓨터의 저장소에 못박습니다.** `-m` 뒤는 나중에 "이게 뭐였지" 할 때 읽는 메모입니다 | 내 컴퓨터에도 안 남습니다 |
| `git push origin <브랜치>` | 내 컴퓨터의 저장소를 **깃허브로 올려 보냅니다.** `origin` 은 깃허브 주소의 별명이고, 뒤의 브랜치는 어느 줄기에 올릴지입니다 | 내 컴퓨터에만 남습니다. 폴더를 지우면 같이 사라지고, 저는 볼 수 없습니다 |

`add` 와 `commit` 이 나뉜 이유는, 고친 것 중 **일부만 골라** 저장할 수 있게 하려는
것입니다. 지금처럼 파일 하나면 굳이 나눌 일이 없어 보이지만 git은 늘 이 두 칸을
거칩니다.

### 안전한가

프로젝트 ID 는 **비밀번호가 아닙니다.** 어차피 APK 안에 들어가 누구나 꺼내 볼 수
있는 값입니다. Expo 공식 문서도 `app.json` 을 저장소에 올리라고 안내합니다.

**부모 PIN·아이 이름·학습 기록은 저장소에 올라가지 않습니다.** 그건 전부 폰 안에만
있고 `app.json` 과 무관합니다.

## 자주 나오는 오류

| 화면에 나오는 말 | 뜻 | 어떻게 |
|---|---|---|
| `Your local changes would be overwritten` | 손댄 파일이 있어 덮어쓸 수 없다 | 그 파일 이름이 같이 나옵니다. `git checkout -- 그파일` 후 다시 |
| `'head' 용어가 ... 인식되지 않습니다` | 리눅스 명령을 PowerShell에서 쓴 것 | [부록 A](#부록-a--리눅스--powershell-명령-대응) 표를 보세요 |
| `'eas' 용어가 ... 인식되지 않습니다` | `eas` 를 못 찾는다 | `npx eas-cli@latest ...` 로 쓰세요. 깔아 두셨다면 **터미널 창을 완전히 닫고 새로** 여세요 |
| `프로젝트 ID가 없습니다` (앱 안에서) | `eas init` 없이 빌드했다 | 5단계 3번 확인 → `npx eas-cli@latest init` → 다시 빌드 |
| `vocab-app 폴더가 없다` | `-b <브랜치>` 없이 clone 했다 | 4-3 을 다시. `main` 에는 README만 있습니다 |
| `Generate a new Android Keystore?` 를 두 번째로 물음 | 열쇠를 못 찾고 있다 | **`y` 하지 마시고** 알려 주세요. 새로 만들면 덮어쓰기가 안 됩니다 |
| 빌드는 됐는데 고친 게 안 보임 | 옛 브랜치에서 빌드했다 | 3단계로. 실제로 한 번 이랬습니다 |

풀리지 않으면 **화면에 나온 글을 그대로** 붙여 주세요. 요약하지 마시고 통째로요.
어느 줄이 원인인지는 제가 봅니다.

## 부록 A — 리눅스 ↔ PowerShell 명령 대응

제가 실수로 리눅스 명령을 드릴 때가 있습니다. 그때 이렇게 바꿔 쓰세요.

| 리눅스 | PowerShell |
|---|---|
| `head -4 파일` | `Get-Content 파일 -TotalCount 4` |
| `cat 파일` | `Get-Content 파일` |
| `grep 무엇 파일` | `Select-String -Path 파일 -Pattern 무엇` |
| `cp a b` | `Copy-Item a b` |
| `mv a b` | `Rename-Item a b` |
| `rm -rf 폴더` | `Remove-Item 폴더 -Recurse -Force` |
| `ls` | `Get-ChildItem` (또는 `ls` 도 됩니다) |

`git` · `npm` · `npx` · `node` 는 윈도우에서도 **그대로** 씁니다.

## 부록 B — 맥·리눅스를 쓰신다면

명령 두 개만 다릅니다. 나머지는 같습니다.

```bash
cp app.json app.json.bak                        # Copy-Item 대신
mv yangpa93 yangpa93-old                        # Rename-Item 대신
```

경로 구분도 `\` 가 아니라 `/` 입니다.

```bash
cd ~/gagavoca/yangpa93/vocab-app
```

## 부록 C — 이 문서에 나오는 말

| 말 | 뜻 |
|---|---|
| **저장소(repository)** | 소스 코드와 그 변경 이력이 통째로 담긴 곳. 깃허브에 있는 것과 내 컴퓨터에 있는 것이 짝을 이룹니다 |
| **브랜치(branch)** | 저장소 안의 작업 줄기. 작업 덩어리마다 새로 만듭니다 |
| **커밋(commit)** | 변경 한 뭉치를 못박은 것. `8d73f57` 같은 번호가 붙습니다 |
| **clone** | 깃허브의 저장소를 내 컴퓨터로 통째로 처음 받아 오는 것 |
| **fetch** | 깃허브의 최신 내용을 받아만 두는 것. 내 파일은 아직 안 바뀝니다 |
| **pull** | 받아서 내 파일에 합치는 것 (`fetch` + 합치기) |
| **push** | 내 컴퓨터의 커밋을 깃허브로 올려 보내는 것 |
| **origin** | 깃허브 주소의 별명. `git push origin ...` 의 그 `origin` 입니다 |
| **EAS** | Expo가 대신 앱을 컴파일해 주는 서비스. 덕분에 안드로이드 SDK를 깔지 않아도 됩니다 |
| **키스토어(keystore)** | 앱에 도장을 찍는 열쇠. 이게 바뀌면 안드로이드가 **다른 앱**으로 봅니다 |
| **APK** | 안드로이드 앱 설치 파일 |
